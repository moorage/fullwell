# Codex Grocery Audit Continuation

## Purpose / Big Picture

Long grocery-order audits can cross Codex's automatic context-compaction boundary. The order checkpoint survives, but the model can still emit an ordinary final response while the audit remains in `collecting`, as happened in session `019fafad-ca33-7a52-9b12-9d52bad678fd`. This change gives the installed Fullwell Codex plugin a narrow lifecycle contract: an audit explicitly arms the current turn, compaction restores only that audit's bounded progress context, and a stop is continued until the audit records a truthful terminal outcome. A new user turn is unarmed by default, so restocking, delivery reordering, meal planning, and unrelated conversation are unaffected unless that turn explicitly starts or resumes a grocery audit.

## Surprises & Discoveries

- 2026-07-29: The failed thread had no tool error, timeout, rate limit, or user cancellation. At 243,408 of 258,400 context tokens Codex compacted automatically, resumed once, then the model emitted a scope correction and `task_complete` while the persisted audit was still incomplete.
- 2026-07-29: `SessionStart` with `source: "compact"` runs before the immediate post-compaction model request, including compaction in the middle of a turn. `Stop` can create a continuation prompt, but plugin hooks are skipped until the user trusts their exact definition.
- 2026-07-29: A session-only marker is too broad. It would let an old audit hijack a later request such as "I'm out of cashews." The continuation must be armed to the exact Codex turn and automatically disarmed at each real user prompt.

## Decision Log

- 2026-07-29: Use Codex plugin hooks rather than transcript parsing, broad prompt matching, a scheduler, or server-side background work. Hooks are the documented point inside the agent loop and require no grocery data or cloud mutation.
- 2026-07-29: Add one Codex-only local MCP lifecycle tool behind a Codex entrypoint flag. Claude continues to expose the existing local tool set and behavior because Claude does not consume these Codex hooks.
- 2026-07-29: Store only an opaque run ID, revision, aggregate order counts, terminal state, current turn ID, and a one-use continuation nonce under `PLUGIN_DATA`. Do not store food, store, order, household, member, URL, browser, credential, or transcript data.
- 2026-07-29: Match continuation by session and current turn, not by semantic keywords. `UserPromptSubmit` disarms an older turn. The exact one-use continuation nonce generated by `Stop` may re-arm its own synthetic continuation prompt without classifying user language.
- 2026-07-29: While an exact turn remains `collecting`, every stop continues. Progress checkpoints and explicit `completed`, `partially_completed`, `blocked`, or `cancelled` transitions are the only normal exits.
- 2026-07-29: Expire coordination records after 30 days and count repeated stops at the same progress revision. Repeated no-progress continuations receive an increasingly explicit requirement to checkpoint real progress or record a truthful terminal state; the hook never invents a terminal outcome.
- 2026-07-29: Apply a lifecycle transition only after parsing a successful result from the exact Codex-only MCP tool. Failed calls, malformed output, lookalike tool names, and unsupported response shapes are inert.

## Context and Orientation

`packages/agent-client/runtime/local-household-mcp.mjs` is the dependency-free local MCP server shared by Codex and Claude. `packages/agent-client/codex-mcp.json` and `packages/agent-client/.mcp.json` are the host adapters. Codex can pass a fixed entrypoint flag so only Codex lists the lifecycle signal.

`packages/agent-client/hooks/hooks.json` will register four handlers implemented by `packages/agent-client/hooks/codex-grocery-audit-lifecycle.mjs`:

- `PostToolUse` consumes only the exact lifecycle tool result and applies validated state transitions.
- `SessionStart` restores compact context only for a collecting audit armed to the interrupted turn.
- `Stop` continues only a collecting audit armed to the current turn.
- `UserPromptSubmit` disarms an old turn, except when the prompt carries the exact one-use nonce created by this hook's own continuation.

The hook state is coordination metadata, not household journal authority. Existing grocery evidence remains in the revisioned local journal or authenticated onboarding checkpoint described by `packages/agent-client/skills/audit-grocery-purchases/SKILL.md` and `packages/agent-client/skills/manage-household-food-journal/SKILL.md`.

### What problem are we actually solving?

The missing capability is not generic background execution. It is a truthful terminal-state guard for one explicitly active, already-checkpointed grocery audit inside the Codex agent loop.

### Roundtable highlights

- Security: keep the ledger private, bounded, atomic, non-semantic, session-hashed, and independent of transcripts or browser data.
- UX: scope enforcement to the exact active turn; a new user prompt must regain control immediately.
- Architecture: keep household data in existing journal/checkpoint authorities and make hooks a disposable coordination layer.
- Reliability: use monotonic revisions, exact transitions, post-compaction context injection, and an explicit terminal call.
- Evals: prove both the 14-minute compaction edge and no-op behavior for every adjacent Fullwell operation class.

### Key tensions

- Persistent completion enforcement versus avoiding an infinite or stale audit that captures future work.
- Shared Fullwell skills and MCP runtime versus Codex-only lifecycle support.
- Enough compact context to resume correctly versus storing private purchase details in hook state.

### Synthesis for decomposition

- Arm only through a purpose-built tool and bind the state to both session and turn.
- Disarm at every real user prompt; re-arm a synthetic continuation only with a one-use exact nonce.
- Keep the state machine strict and privacy-bounded, and fail closed on malformed or conflicting lifecycle calls.
- Test positive compaction/stop behavior before updating agent instructions, then test broad negative isolation.

### Pre-implementation critique

The proposed feature is a Codex-only continuation guard around an existing durable grocery audit, not a general background worker. The hook must keep the exact collecting turn alive without acquiring household authority or affecting later work.

- Security critic - Fragile assumption: any matching post-tool event is trustworthy. Required change: require the exact canonical tool name, a successful parseable MCP result, closed-world fields, session hashing, symlink rejection, private modes, and no transcript access.
- Reliability critic - Fragile assumption: a continuation marker cannot be replayed or become stale. Required change: bind the one-use nonce to run and revision, consume it once, expire state after 30 days, and reset same-revision stop counters only on a real checkpoint.
- UX critic - Fragile assumption: session scoping alone protects later requests. Required change: every normal `UserPromptSubmit` disarms the old turn while retaining recoverable aggregate state; an unrelated turn then receives no context and no stop decision.
- Host-compatibility critic - Fragile assumption: adding a shared MCP tool is harmless on Claude. Required change: gate the lifecycle tool behind the fixed Codex entrypoint flag, assert Claude's tool list is unchanged, and bundle hooks only in the Codex manifest/package path.
- Evals critic - Missing validation: positive continuation tests alone can hide broad interception. Required change: exercise malformed and failed lifecycle results, nonce replay, expiry, symlink state, every non-lifecycle Fullwell tool class, and unrelated prompts/events.

Must fix before implementation: all five changes above. Should fix if low-cost: include an explicit stalled-continuation instruction after repeated stops at one revision. Monitor during implementation: the current Codex host lifecycle may discover an untrusted hook but cannot automatically grant trust; manual release evidence must retain that user-controlled boundary.

## Acceptance / Verification

- The original edge is represented: an armed collecting audit survives a simulated `SessionStart(compact)` and a simulated `Stop` returns `decision: "block"`.
- A synthetic stop continuation re-arms exactly once; a normal new user prompt disarms the old turn without interpreting prompt text.
- A terminal lifecycle transition makes later `Stop` and `SessionStart` calls inert.
- Restock, delivery reorder, meal planning, other Fullwell tools, and unrelated tool/chat events never create or arm audit hook state.
- The hook never reads `transcript_path` or stores private food, store, order, browser, household, member, URL, or credential fields.
- Failed, malformed, stale, expired, symlinked, lookalike, and replayed lifecycle events fail closed without arming an audit.
- Codex package install exposes the lifecycle tool and hook definition; Claude install retains the prior local tools and has no hooks.

## Idempotence and Recovery

`begin` is idempotent for the same run and aggregate counts. `resume` requires the exact current revision. `checkpoint` requires the exact current revision and nondecreasing completed-order count. `finish` requires the exact current revision and removes the active coordination record only after the terminal tool call succeeds. Malformed, stale, cross-run, or failed tool calls do not arm continuation.

If Codex hooks are disabled, untrusted, unavailable, or fail, the existing audit checkpoint remains the recovery authority and the skill must report that continuous execution cannot be guaranteed. Reinstalling or rolling back the plugin does not mutate journal data.
